# 7TV channel sync (panel)

The panel side of core's experimental 7TV sync ([../core/7tv-sync.md](../core/7tv-sync.md): scope, API, settings, advanced rules, review reasons). Paths are relative to `apps/web`.

## Where it lives

- **Route** `/panel/servers/$guildId/sync` (`routes/panel.servers.$guildId_.sync.tsx`). The `_` suffix makes it a sibling of the server route under `/panel`, not its child: the server page has no outlet. Same guild check as the server page (manageable servers only, inline "server not found" otherwise). Header crumb `panel / <server> / 7TV sync` (the server crumb links back, hidden below `sm`). Not a `?view=` tab of the server page: the emotes toolbar (filter, type, sort) doesn't apply to setup, settings and emotes that aren't on the server.
- **Way in**: `StvSyncTile` next to the slot meters on the server page: "following <channel>" / "paused on <channel>" / a setup line, "3 need review" in orange (`needReviewLabel`), "manage" / "set up". Hidden when the sync isn't available and nothing is linked, or while its query loads or fails. Its query doesn't poll.
- **Components** (`components/panel/`): `stv-sync.tsx` (`StvSync` page body, status, link form, `StvSyncTile`), `stv-sync-review.tsx` (needs review), `stv-sync-settings.tsx` (the form), `stv-sync-rules.tsx` (the rule builder), `stv-sync-save-bar.tsx` (save bar + leave guard), `unlink-sync-dialog.tsx` (ui-sdk alert dialog, as `DiscardTaskDialog`).
- **Data** (`lib/stv-sync.ts`): `syncQueryOptions(id)` (`["stv-sync", id, "state"]`) and `syncReviewQueryOptions(id)` (`["stv-sync", id, "review"]`), both refetched every 30 s while shown (connection state, counts and new entries change on their own); `syncKey(id)` invalidates both. Types come from the client (`SyncState`, `LinkedSync`, `SyncSettings`, `ReviewEntry`). `syncErrorMessage` handles the sync codes (`REVIEW_ENTRY_NOT_FOUND` …) and falls back to `emoteErrorMessage`; `connectionStatus` turns `connection` + `sync` into one line. The own key root keeps them out of `["guilds"]` invalidations.
- **Rules** (`lib/stv-sync-rules.ts`): `FIELDS` (label, group, operators with labels, value kind, default value, `costly` for file/server facts) mirrors core's condition table; `SyncRule`, `RuleCondition`, `RuleField` come from the client types. Drafts (`DraftRule`, `DraftCondition` with a client `key` and the value as typed text) ↔ API rules (`toDraftRule`, `toRules` → `{ rules, errors }` keyed by condition key, `normalizeRules`). `RULE_LIMITS`, the nested-quantifier check and `new RegExp(p, "i")` mirror core's schema, so the form says what's wrong before saving. The one cast in the web sync code is there: TypeScript can't tie a draft's field, operator and parsed value to one branch of core's union.
- **Draft** (`lib/stv-sync-settings-draft.ts`): `useSyncSettingsDraft(guildId, saved)` holds filters, `maxAspectRatio` and rules; `excludedEmoteIds` is never in it (sent back as saved). `dirty` compares signatures without condition keys. A refetch with other saved settings replaces a clean draft and leaves a dirty one alone. Saving normalizes the drafts first (trimmed text, `3.0` → `3`, keys kept), so after the save the form is clean without remounting a row.
- **Writes** (`lib/stv-sync-mutations.ts`): every state-returning write puts the answer into the state query and invalidates `syncKey`, so the review list and counts refetch after any write.

## What the user sees

- Header: server icon, "7TV sync" with a `Badge tone="signal"` "experimental" (the view's one signal element), a `← <server>` link, and a `Notice` "experimental: this may behave unpredictably" explaining events-only.
- `available: false`: "the 7TV sync isn't active on this tetra instance", no setup. With a channel still linked, the status box, needs review and settings stay (status "off on this tetra instance"), so it can be unlinked.
- Not linked: `ChannelSearch` (the channels page's autocomplete); choosing a channel sends `PUT { login }` at once, "linking <login>" while it runs, errors inline.
- Linked: channel display name (login when it differs), linked time, "open on 7TV ↗", unlink (confirm says the emotes stay, links and needs review go); status (orange square when connected and following the set, `Spinner` while connecting, grey otherwise; "paused", "no active 7TV set" win), synced and needs review counts; "sync new emotes" `Switch` = `PATCH { enabled }`, showing the requested value while it runs.
- **Needs review**: rows with the 2x preview on `bg-checker`, `:discordName:` (the 7TV alias when it differs), type · size · author · relative time (`flaggedAt`), the API's `message` as is (it says "it matched rule 2" for `RULE`). Retry (toast: added / "still needs review" with the new message as a plain toast, not an error / already synced), open in editor (see [editor.md](editor.md#7tv-sync-review-target)), dismiss ▾ (`dismiss` / `dismiss and never sync it` = `?exclude=true`). A line above says freed slots never retry on their own and retry skips filters and rules.
- **Settings**: filters, advanced filters, optimization in one `form` (Enter in a field saves), then "never sync", then "reset all settings to defaults" (the API's `defaults`, into the draft, not saved).
  - Filters: four switches only (static, animated, skip zero-width, skip sensitive). The NSFW flag is "sensitive" everywhere: 7TV's flag covers more than sexual content, so the copy never says "sexual" (`skipNsfw` keeps its key). Caught emotes need review, they're never dropped.
  - Optimization: max aspect ratio `Slider` 1–4, step 0.1, shown as `2.0:1`, rounded to one decimal on change. The shape/fitting picker is gone: core always fits with `contain`.
  - Never sync: count + "clear", saved on its own from the stored settings with its own toast, so it never touches the draft.
- **Rule builder** (heading "advanced filters"): a line on the semantics (top to bottom, first match wins, no match = added as usual, not on retry), then an `ol` of cards.
  - Card header: a `Switch` labelled "rule N" (N = position, disabled rules count; off adds "off. the sync passes over it" and dims the body), ↑ / ↓ (`focusableWhenDisabled` at the ends) and remove.
  - Condition rows: `if` / `and`, a field `Select` grouped name / on 7TV / file / server (`SelectGroupLabel`), an operator `Select` (hidden when the field has one operator), the value. Booleans fold into a yes / no `Select` instead of operator + value ("listed on 7TV · no"). Numbers are a `TextField` with the unit as suffix (`px`, `KB`, `s`, `days`, `:1`, `chars`, `frames`, `slots`) and `inputMode`; `matches pattern` gets `/…/i` affixes; `is one of` / `isn't one of` take comma-separated users with a count below. Changing the field resets operator and value to the field's defaults; changing only the operator keeps the text (one user → a list just works). A muted hint per field sits under the row unless there's an error. × removes a condition (not the last one); "+ and" adds one, up to 5, and "all of them have to match" shows from two.
  - A note appears when a file or server condition comes before a cheaper one: tetra downloads or asks Discord first, so put the others above.
  - `then` `Select`: hold for review / skip / add, with a line on what each does (add still applies aspect ratio, free slots and 256 KB; skip never shows in needs review).
  - Below the list: "+ add rule" (name contains …, hold for review), "from a preset ▾" (a `Menu`: long animations, big files, renamed, skip some authors, added by someone else; presets without a value focus the value field), "reset rules to defaults" when they differ. 25 rules is the cap (buttons off with a line saying so). Ids are `rule-<8 base36>`, unique in the list.
  - Focus: moving keeps focus on the pressed arrow, removing a rule goes to the next (or previous) rule's switch or "+ add rule", removing a condition to its neighbour's field select, adding goes to the new field select. Done with a selector picked before the update and focused in a layout effect, since React moves keyed nodes and a moved focused node can lose focus.
  - No drag and drop: arrows cover reordering from the keyboard and on touch.
- **Save bar** (`StvSyncSaveBar`): fixed to the bottom of the content area (`left: var(--panel-inset)`, like the emote selection bar: `h-14`, `bg-surface`, hairline top, safe-area padding), shown while a channel is linked: "all changes saved" (muted) / orange square + "unsaved changes" / Spinner + "saving", "fix the marked fields to save" or the save error in `danger` below it; "discard" while dirty, primary "save" (off when clean, invalid or saving). Nothing hides under it: the panel's `main` has `pb-16`, more than the bar's height. `data-settings-bar` lifts the toaster and sets `scroll-padding-bottom`.
- **Leave guard** (`UnsavedSettingsGuard`): TanStack Router `useBlocker({ shouldBlockFn, enableBeforeUnload, withResolver: true })` reading a ref of `dirty`. In-app navigation (links, back, "open in editor") opens a controlled ui-sdk `AlertDialog` "leave without saving?" with "keep editing" (default focus, `reset()`) and "leave" (`proceed()`); a reload or closing the tab gets the browser's own `beforeunload` prompt, the only option there.
- A 400 `INVALID_REQUEST_SCHEMA` on save is explained as a pattern core rejected (its nested-quantifier check runs on the server too).
