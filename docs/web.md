# Tetra web

Website and panel (`apps/web`). Paths in this document are relative to `apps/web`.

**Stack:** TanStack Start (Vite), TanStack Router (file-based routes), React 19, TanStack Query, TanStack Virtual (long emote lists), Tailwind CSS v4, ui-sdk (unstyled accessible components, see [ui-sdk](#ui-sdk)).

## Rendering

- **SPA mode** with selected pages prerendered. There is no server at runtime: the build output is static files.
- **Homepage** (`/`) and other public pages: prerendered to HTML at build time. Add their paths to `staticPages` in `vite.config.ts`, and link them from the footer (`PAGES` in `src/components/footer.tsx`). Public pages use the shared `Navbar` and `Footer`. A new page also needs its SEO entry, see [SEO](#seo).
- **Editor** (full name "Image/GIF quick editor"): public, no account, for GIFs and still images (not only emotes). `/editor` (start screen with upload and recent files, then a prerendered how-it-works + FAQ section for search, and the site `Footer`) is prerendered; `/editor/$key` (a file stored in this browser) is client-only (`ssr: false`), served by the SPA shell like the panel. See [web/editor.md](web/editor.md).
- **Panel** (`/panel/*`): client-only (`ssr: false` on the route). Served by the SPA shell `_shell.html`; the host must rewrite unknown paths to it. Every panel route sits behind the session gate, see [Panel auth gate](#panel-auth-gate).
- The shell is rendered with `spa.maskPath: "/panel"` so it doesn't collide with the prerendered `/`.
- In `vite dev` every route renders on the client, including `/`.

## Styling

Tailwind v4, configured in CSS (`@theme` in `src/styles/app.css`); dark only. The design rules behind the tokens are in [branding.md](branding.md) (rendered as the brand book at `/branding`).

- **Fonts:** `font-sans` = Geist (default for everything), `font-serif` = Geist Serif (display serif with a single 400 weight, use only as an accent for headings), `font-mono` = Geist Mono (ASCII-art accents, also used by the homepage background glyphs).
- **Utilities** (defined with `@utility` in `app.css`): `bg-checker` = the quiet transparency checkerboard behind emote previews; `bg-dots` = faint dot grid of a workspace behind a movable window.
- **Radius:** every `--radius-*` token and `--ui-radius` is 0; never use `rounded-full`.
- **Colors** (OKLCH): `brand-50…950` built around `#f64f02` (`brand-500`); `neutral-*` is Tailwind's scale with a faint tint of the brand hue. `signal-300/400/500` is the rare cool accent. Prefer the semantic tokens: `background`, `surface`, `foreground`, `muted`, `border`, `primary`, `primary-hover`, `primary-foreground`, `signal`, `signal-foreground`, `danger` (errors and invalid fields only, also mapped to ui-sdk's `--ui-destructive`). Text on `primary` is dark (`primary-foreground`), white on the orange fails contrast.

## UI components

Our components live in `src/components/ui/`, one file per component, kebab-case. Use them instead of styling raw elements; every component is shown on the brand guide (`/branding/guide`, components section), so add new ones there too.

- `Button` – wraps ui-sdk's `Button`. `buttonClassName({ variant, size })` gives the same look to ui-sdk parts that are buttons themselves (a dialog's trigger or close). `variant`: `primary` | `secondary` (default) | `destructive` (secondary with orange text: Remove in the selection bar) | `ghost`; `size`: `sm` | `md` (default) | `lg`; `glow` only on the page's main call to action. No transitions and `cursor-default` by design (native feel, see branding.md); each variant has hover and `active` states. Links: `render={<a href=… />}` or `render={<Link to=… />}`, never a styled `<a>`. Children can react to hover with `group-hover/button:`.
- `Heading` – `level` (1–6) sets the tag, `size` (`display` | `xl` | `lg` | `md` | `sm`) the look; each level has a default size. Pick the level for the document outline, never for the look.
- `Text` – paragraph, `size` (`lg` | `md` | `sm` | `xs`) and `tone` (`default` | `muted`).
- `Accent` – the serif brand word inside a heading.
- `Eyebrow` – mono label above a heading; `index="01"` renders `[01] /`.
- `Radio` + `RadioGroup` (`radio.tsx`) – ui-sdk radio: a square box with an orange square inside when checked, no transition. Only the control: wrap it with its text in a `<label>` (as ui-sdk documents; Biome needs a `noLabelWithoutControl` ignore there). `RadioGroup` is ui-sdk's, re-exported (one tab stop, arrows skip disabled radios). web.css rounds radios (`border-radius: 50%`) and nudges them down inside a label, so `Radio` pins `rounded-none` and `my-0`. For a few options that should all be visible; no panel screen uses it right now (Quick add's server moved to `Select`). (A `Checkbox` existed for the multi-server add and was removed with it.)
- `Select` parts (`select.tsx`) – ui-sdk's select with our look: `SelectTrigger` (looks like `TextField`'s input, `h-9`, mono `▾` on the right, web.css's chevron hidden, `data-placeholder` in `neutral-500`), `SelectContent` (the menu's popup: hairline border, `bg-background`, `--anchor-width` wide, at most 20rem tall), `SelectItem` (menu row height, orange square on the left for the chosen one, disabled rows in `muted` and `not-allowed`, still listed); `Select`, `SelectLabel`, `SelectValue`, `SelectItemIcon`, `SelectValueIcon` re-exported. Put `label` on an item whose content carries extra text (a slot count), so typeahead matches only the name. For a value picked from a list that can be long (Quick add's server). Pinned in full, so it looks the same without web.css.
- `SegmentedControl` + `SegmentedControlItem` – wraps ui-sdk's segmented control; for switching between a few views or modes. `size`: `md` (default, 28 px items) | `sm` (20 px items, `text-xs`, for a window title bar or a pane's footer row; the items read it from context). The indicator jumps without a transition (native feel). `onValueChange` passes `string | null`.
- `Slider` – labeled single-value slider (ui-sdk `Field` + `Slider`): `label`, `value`, `onValueChange`, `min`, `max`, `step`, `format`. Square white thumb, orange fill, value in mono on the right. `onValueChange` fires on every drag step so derived numbers follow the thumb live. For a range or a custom track (the trim timeline), compose ui-sdk's slider parts directly.
- `TextField` – label + input + description/error (ui-sdk `Field`, `InputGroup`, `Input`). `disabled` disables the `Field` (out of the tab order, value kept, muted text, hairline border; Browse's search while BTTV is picked). `prefix`/`suffix` render mono affixes (`:name:`); `action` puts a control right of the input, stretched to its height (Quick add's Search button); `hideLabel` keeps the label for screen readers only (a search box); `error` replaces the description and marks the field invalid. Validate inline as the user types, never only on submit. Passes `name`, `type` (`url` / `search` for the right on-screen keyboard), `inputRef`, `onPaste` and `onKeyDown` to the input.
- `Switch` – labeled on/off row (ui-sdk `Switch` inside a `<label>`): `label`, `checked`, `onCheckedChange`, optional `description`. For settings that apply immediately.
- `Notice` – non-blocking heads-up: mono `[!]` in orange, `title`, body, optional `action` on the right. Bordered box by default; as a full-width bar under a toolbar pass `className="border-x-0 border-t-0"`. Errors that stop a task stay inline in `text-danger` instead.
- `Spinner` – braille dots chasing around one cell (`⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`, 120 ms per frame), in orange, `aria-hidden`. Braille frames all have the same width and weight; an ASCII-ramp version was tried and rejected because the glyphs jumped. Always pair it with text saying what's happening; with reduced motion it stands still.
- `SlotMeter` – emoji slots of one type (ui-sdk `Meter`): `label`, `used`, `limit`. Mono label and `used/limit`, thin bar; bar and number turn orange in the last 10% of slots (at least 1). Screen readers get "47 of 50, 3 free" / "50 of 50, full".
- `Menu` parts (`menu.tsx`) – ui-sdk's menu with our look: `MenuContent`, `MenuSubContent`, `MenuItem` (`variant`: `default` | `destructive` (orange, never `danger`) | `info` (a read-only line: disabled but not dimmed, still reachable by keyboard)), `MenuSubTrigger` (`›` on the right; menus use text glyphs, never icon components: `›` for a submenu, `↗` + U+FE0E (text presentation, no emoji on Apple) right after the label, not pushed to the end, for a link that opens in a new tab; bare ASCII `>` / `^` was tried and rejected as ugly), `MenuRadioItem` (orange square for the checked one), `MenuGroupLabel` (mono), `MenuSeparator`; the unstyled parts (`Menu`, `MenuContextTrigger`, `MenuSub`, `MenuGroup`, `MenuRadioGroup`, `createMenuController`) are re-exported. Popups keep 8px from the viewport edges; under 640px submenus open below their trigger. Pinned in full, so it looks the same without web.css.
- `Toaster` + `toast` (`toaster.tsx`) – ui-sdk toasts: a region bottom right, always expanded (up to 4, newest at the bottom), square, `bg-surface`. The type shows as a mono glyph: Spinner (loading), `+` orange (success), `-` danger (error). Mounted once in `PanelLayout` (and on `/branding/guide`, and lazily on `/editor/$key` once the user can add to a server); call `toast()`, `toast.success/error`, `toast.promise()` from anywhere.
- `SizeMeter` – file size against a limit (ui-sdk `Meter`): `value`, `limit` (bytes), optional `max` where the bar ends (pass the original size so the overflow reads as a distance to cover). Shows size / limit in KB/MB, % of the limit, a tick at the limit and the part over it in orange, with "X over · reduce by Y%" or "Fits · X to spare". Screen readers get one sentence via `getValueLabel`.

These components are styled entirely with Tailwind, without relying on ui-sdk's `web.css`, so they look the same on prerendered pages (like `/branding/guide`) that don't load it.

Raw `h1`–`h6` get only font weight, tracking and balanced wrapping from `@layer base` (no size), so unstyled content still looks on-brand.

Components accept `className` for layout (margins, width, animation); don't use it to change colors or sizes the variants already cover. Variants are plain objects in the component file; add a variant there rather than overriding at the call site.

## ui-sdk

`@ui-sdk/react` + `@ui-sdk/core` (Vercel Labs, beta, pinned to an exact version): unstyled components with keyboard, focus and ARIA handled (dialog, menu, select, tabs, toast, combobox, image-cropper…), plus `@ui-sdk/core` behaviors for building components it doesn't ship.

- **Before using it**, follow the ui-sdk skill (`.claude/skills/ui-sdk`, loaded automatically by Claude Code). Then read `node_modules/@ui-sdk/react/docs/llms.txt` and only the pages the task needs (e.g. `docs/components/select.md`). To build a new component, also search `node_modules/@ui-sdk/react/docs/core.md` by heading (it's huge, don't read it whole) and read `rendering.md` next to it.
- Import each component from its own entry (`@ui-sdk/react/dialog`); there is no root import.
- **Default look:** `@ui-sdk/core/web.css`, imported by `src/styles/ui-sdk.css` as `@import "@ui-sdk/core/web.css" layer(components);`. Inside the components layer it sits above Tailwind's preflight (which would reset it otherwise) and below utilities, so Tailwind classes win. `ui-sdk.css` is imported only in lazy route files (`panel.lazy.tsx`, `editor.index.lazy.tsx`, `editor.$key.lazy.tsx`), so other pages don't download it: a side-effect import in a non-lazy route file ends up in every page's HTML. Some parts rely on it for layout (image cropper handles), the components in `components/ui/` don't. Once loaded it's global for the rest of the visit, so a page that shows a ui-sdk part both before and after another route loaded it must import it too, or pin every property web.css sets (the quick editor's drop zone changed font size otherwise).
- web.css underlines every `<a>` (and sets its color), so `Button` carries `no-underline` for `render={<a … />}`; pin the same on any other link-based part used on a page that loads it.
- Its `--ui-*` tokens are mapped to our theme in `src/styles/app.css`; restyle parts with Tailwind on top (`data-slot` and state attributes like `data-open:`), never `!important`.
- `@layer ui-sdk;` stays at the very top of `app.css`, above `@import "tailwindcss"`: ui-sdk injects some behavior CSS into that layer at runtime.
- Our own `color-scheme: dark` overrides web.css's light/dark switching.
- Form parts (slider, switch, input…) render hidden inputs with `position: absolute` (`hiddenInputStyle` in `@ui-sdk/core` `foundation/forms/form.js`). Inside a scroll container, give the container or an ancestor `position: relative`: otherwise they're placed against the page and make it scroll (the editor's sidebar did, even under an `overflow: hidden` root).
- Route files may use TanStack's dotted names and `$params` (`panel.lazy.tsx`, `editor.$key.lazy.tsx`, `panel.servers.$guildId.tsx`), an exception to kebab-case.
- `web.css` draws icons with pseudo-elements on parts without an `svg` child: a chevron `::after` on a submenu trigger (`menu-trigger` inside `menu-content`) and an × `::before` on `toast-close`. Ours bring their own glyphs and hide these (`after:hidden`, `before:hidden`).
- `AutocompleteEmpty` (and other list `Empty` parts) with a function child calls it on every render, items or not: only plain children are hidden by `state.empty`. Return `null` when `!state.empty` (the channel search showed "no channel matches" above its results otherwise). The part's element stays in the DOM when it returns `null`, so its padding classes need `empty:hidden` (web.css pads it only `:not(:empty)`).
- `web.css` styles `menu-trigger`, `drawer-trigger` and `drawer-close` as bordered buttons and `drawer-content` with padding, a border and a shadow; the panel pins border, background, height, padding and shadow on them with Tailwind.

## Talking to the API

The API lives in core (`/api`, see [core.md](core.md#api)). `src/lib/api.ts` exports a typed Hono RPC client and `unwrap`:

```ts
const guild = await unwrap(api.guilds[":guildId"].$get({ param: { guildId } }));
```

- Paths, params, bodies and success responses are typed from core's route code; there are no hand-written API types. Dates arrive as strings (the types follow JSON).
- `unwrap` returns the body of a 2xx response (`undefined` for an empty one: 204, and `/me/state`'s empty 200) and throws `ApiError` (`status`, `message`, `reference` = the API's error code) otherwise. Error bodies are not in the client types, branch on `status` / `reference`.
- `unwrapBlob` is the same for endpoints that answer with a file (`GET /tasks/:id/file`): the body as a `Blob`, `ApiError` from the JSON error body otherwise.
- The `QueryClient` (`src/router.tsx`) doesn't retry a 4xx `ApiError` (network errors and 5xx get the default 3 tries), and any query or mutation failing with 401 invalidates the session query, so the panel falls back to the login screen when a session ends mid-use. Panel code doesn't handle 401 itself.
- Base URL: `VITE_API_URL` (default `http://localhost:3002`). Requests send the `tetra-session` cookie (`credentials: "include"`, `sameSite: lax`), so web and API must be on the same site; any port on localhost works in development.
- **How the type gets here**: `@tetra/core` is a workspace dependency exporting `./api` (`src/api/app.ts`), imported with `import type` only, so nothing from core is bundled. Both apps use the `@/` alias for their own `src`, so the web program can't compile core's sources itself: `tsconfig.json` has a project reference to `../core/tsconfig.api-types.json`. `tsc -b` (the `typecheck` script) builds core's declarations into `apps/core/dist/types` incrementally; editors read core's sources directly, so new routes show up without a build.
- **Rejected alternatives** (2026-11): moving core's aliases to package.json `imports` would let web compile core's sources directly, but means rewriting ~320 imports in core and pulling Bun's global types into web. A separate `packages/contract` with hand-written Zod response schemas (keeping Express) was rejected because nothing checks that handlers return what the schemas promise; that drift is what broke the old `tetra-next` panel's hand-written types.

## Panel auth gate

`/panel` is a layout route: `routes/panel.tsx` (`ssr: false`, `validateSearch` for the optional `error` param, inherited by children) and `routes/panel.lazy.tsx` (the gate). Child routes (`panel.*.tsx`, see [Panel routes](#panel-routes)) render through its `<Outlet />` only with a session.

- **Check**: `sessionQueryOptions` (`["session"]`) calls `GET /api/me/state`: 200 → `true`, 401 → `false`, anything else throws (1 retry). Pending shows `Spinner` + text; an error (API down, 5xx) shows an inline `text-danger` message with Retry, never the login screen.
- **Logged out**: `PanelLogin` on `PanelScreen` (no public navbar/footer). The button is a plain navigation to `loginUrl(returnPath)` = `${VITE_API_URL}/api/auth?redirect=…` (built with the client's `$url()`, so the base URL lives only in `lib/api.ts`); `returnPath` is the current path + search without `error`. Core accepts only `/panel…` paths and brings the user back there.
- **Callback errors**: core redirects back with `?error=<CODE>` (`AUTH_CALLBACK_ERRORS` in core's `auth.shared.ts`); `PanelLogin` maps `ACCESS_DENIED`, `INVALID_OAUTH_STATE`, `RATE_LIMITED` to a `Notice`, everything else to a generic "on our side" message. When the session is valid anyway (a failed re-login keeps the old session) the gate strips `error` with a `replace` navigation.
- **Logged in**: the gate renders `PanelLayout` around the `<Outlet />`.
- **Log out** (user menu): `POST /api/auth/logout`, then sets the session query to `false` and removes every other query, so nothing of the previous user stays cached. The session query itself is kept: the gate observes it, and a removed query would leave the observer on a stale instance.
- **Expiry**: a 401 anywhere invalidates the session query (see [Talking to the API](#talking-to-the-api)), the recheck returns `false` and the gate shows the login screen.

### Quick add

One field: search 7TV or paste a link. `QuickAdd` (`components/panel/quick-add.tsx`) is inline on Home and (compact, label hidden, preset to the server) in the server view, and inside a dialog from `QuickAddProvider`.

- **Link or text**: `looksLikeEmoteLink` (an http(s) URL or `<a?:name:id>`) decides. A link resolves; any other text never does (no "unsupported link" errors while typing a word).
- **Search** (`TextField` `action`): disabled under 3 trimmed characters and while the text is a link (links resolve on their own; disabling instead of hiding keeps the field from jumping). Enter or the button on plain text navigates to `/panel/browse?q=<text>` (7TV), with `&guild=<id>` when Quick add has a preset server (the server view), so Browse offers that server first. In the dialog it also closes the dialog (`onSearch`).
- **Resolve** (links only): `GET /emotes/resolve` 500 ms after typing stops, at once on paste (the input's value is read on the next tick) or Enter; Enter on an error retries. Errors show under the field with `lookupErrorMessage`.
- **Form** (keyed by the emote, so a new link resets it): the `Emote` preview inside its own `EmoteMenu kind="catalog" selectable={false}` (right-click works and carries the edited name; no selection bar, the form is those actions), source · type · pixel size, the name (`toDiscordEmoteName` of the source's name, validated inline; a hint says when it was cleaned up or the link had none), the server (a `Select` of manageable servers: icon, name and "N free" for the emote's type, full ones listed but disabled with "animated full" / "static full"; the trigger shows the picked server's icon and free slots), the fitting (`SegmentedControl` bound to the menu's per-emote fitting, so the tile preview and Temporary fitting follow it). "add to <server>" sends one `useAddEmote`; "open in editor" next to it puts the emote (with the edited name) into the editor through `useEditInQuickEditor` (`/panel/editor/<key>`; the dialog closes once it opened).
- **One server per add.** Adding to several servers at once (a checkbox list, one request per server) was built and removed (2026-11, owner's call): one target keeps the form and the outcome simple; Browse's right-click "Add to server ›" covers another server.
- **Default server only when certain**: the preset (`defaultGuildId`: the server view, or a dialog opened with `guildId`), else the only manageable server; otherwise nothing is picked and the button reads "pick a server". A default without room for the emote's type leaves nothing picked too. Remembering the last picked server (`localStorage` `tetra:quick-add-target`) was removed (2026-11): on Home a pasted link showed "Add to <some server>" for a server the user hadn't chosen this time. The radio list of every server became a `Select` (a long list with many servers, and nothing needs to be visible before picking); it is the one picker in all three places (Home, server view, dialog). All panel copy (nav, crumbs, headings, buttons, toasts, errors, aria-labels, page titles) follows voice.md: lowercase, no trailing period, no `…` in loading text; errors where tetra failed are in first person (`i couldn't load your servers`), tetra on a server stays third person (`tetra isn't on this server`).
- **After success**: inline, the field clears and keeps focus for the next link; in the dialog, the dialog closes. A failure keeps everything for a retry.
- **Dialog** (`QuickAddProvider`, `useQuickAdd()(request)`): opened with `{ text }` and by a **global paste**: a `paste` on the document whose target isn't an input, textarea, select or contenteditable, with no files, and text matching `looksLikeEmoteLink` (links only; pasted plain text is ignored). Not on the editor's routes (`/panel/editor`, `/panel/editor/$key`): there a paste belongs to the editor, whose start screen opens links itself (see [web/editor.md](web/editor.md#opening-a-link)). Initial focus: the field (`initialFocus` by `input[name="emote-query"]`). Placed at the top (`mt-[8vh]`), never centered.

### Browse

`/panel/browse?provider=ffz|bttv&q=…&guild=<id>` (7TV is the default and stays out of the URL). Provider `SegmentedControl` and a search field that writes `q` 300 ms after typing (replace navigation, so it's linkable and survives reload; back/forward writes the field). Quick add's Search lands here too.

- **All search runs in the browser** (`src/lib/providers/`); web never calls core's `GET /emotes/search` (2026-11, owner's call: the proxy added nothing for public, CORS-enabled APIs; core drops the endpoint). Verified 2026-11 from `http://localhost:*`: 7TV's `https://7tv.io/v3/gql` answers the `content-type` preflight and the POST with the request's origin in `Access-Control-Allow-Origin`; FFZ's `https://api.frankerfacez.com/v1/emotes` sends `*`. The clients mirror core's lookups exactly: 7TV v3 GraphQL (search text as a variable, `TOP` category for an empty query, 60 per page, file 4x GIF/PNG then WebP, preview `2x.webp`), FFZ `sort=count-desc` (empty = most used), animated as `.webp` (see below), page cap 100. The `url`s are on `cdn.7tv.app` / `cdn.frankerfacez.com`, which core's `assertAllowedEmoteSourceUrl` accepts for the add endpoint.
- **FFZ animated emotes are fetched as WebP.** Verified 2026-11-16 with curl: `cdn.frankerfacez.com/emote/<id>/animated/<n>.gif` is generated on demand and unreliable per emote and size (725750 served 4/2/1.gif; 743169 served 4.gif but 2.gif and 1.gif hung, 25 s, 3 tries; 724094 4.gif answered 522 after 20 s, then hung), while `animated/<n>` and `animated/<n>.webp` answered 200 `image/webp` in ~0.5 s every time, CORS `*`. The editor converts such a WebP to GIF on import (see [web/editor.md](web/editor.md#animated-webp)). core's `ffz-lookup.ts` picks WebP for the same reason.
- Responses are checked with Zod; a shape that doesn't match throws `ProviderError` `changed` ("…answered in a shape i don't know"), and the issues go to the console, so a provider API change shows as an error, not an empty grid. 429 → `rate-limited` (7TV allows 100 searches a minute per IP). Changed and rate-limited aren't retried; network errors once.
- TanStack Query's `signal` goes to `fetch`: a query that changes aborts the request in flight.
- What went away with the proxy: core's 5-minute Redis cache shared by all users (each browser now caches 5 minutes itself) and core's 10 s upstream timeout. FFZ's empty-query `count-desc` list takes 11–15 s at FFZ itself (measured 2026-11; a search takes ~0.4 s), which core's timeout turned into an error; the browser waits it out under "loading most used on FFZ".
- **BTTV is temporarily disabled**: no working client-side search yet. It stays in the provider switch (users see it's coming); picked, it shows a `Notice` ("BTTV is temporarily disabled…paste a BTTV link into quick add") with a "quick add" button that opens the dialog, disables the search field (`?q` stays in the URL for the other providers) and sends no request. The segment itself stays enabled: a disabled segment can't explain itself (no tooltip on touch, skipped by arrow keys). Pasted BTTV links still resolve through `GET /emotes/resolve`.
- Results: `useInfiniteQuery` + `EmoteGrid` (`onEndReached` loads the next page about 6 rows before the end), items deduplicated by key across pages, inside `EmoteMenu kind="catalog"` with the `guild` param as the preferred server. Keyed by provider + query, so fittings reset; a new query or provider drops the selection (the emote leaves the list).
- Titles: "top on 7TV", "most used on FFZ" for an empty query, "“q” on 7TV" otherwise. Loading, errors and "end of the list · N emotes" sit inline under the grid, never centered; a failed next page shows its error with Retry under the grid.
- **Left click selects** and brings up the selection bar (add to <guild> / add to server ▾, download, open in editor, more); right-click / long press has the same actions as the catalog menu (see [web/emote.md](web/emote.md#selection)). Opening Quick add with the clicked emote was tried and removed.
- Verified with 10 pages of 7TV (600 emotes): about 165 tiles and 925 elements in the DOM. With the direct clients, 14 pages (840) loaded by scrolling.

### Channel emotes

`/panel/channels?channel=<login>&provider=twitch|7tv|bttv|ffz&guild=<id>` (`channel` is checked with `parseTwitchLogin` and lowercased; `provider` only once a tab was clicked, replace navigation; choosing a channel pushes, so back goes to the previous one). Sidebar entry and header crumb "channels" (after browse).

- **Search**: `ChannelSearch`, a ui-sdk `Autocomplete` (`filter={false}`, `submitOnSelect`) with a `twitch.tv/` prefix. `GET /twitch/channels?query=` 300 ms after typing stops (core's API allows ~120 requests a minute per IP), not for the login already in the URL. Suggestions (partners, then affiliates, then the rest, sorted by core): avatar, display name, login when it differs from the display name, a mono `partner` (orange outline) or `affiliate` (neutral outline) tag, an orange square + `live`. Choosing one, or Enter on a login / `@login` / `twitch.tv/…` link, sets `?channel`; anything else gets an inline error. The popup is anchored to the whole field (`anchor`), not only the input.
- **Channel**: `GET /twitch/channels/:login`; 404 `CHANNEL_NOT_FOUND` is a muted line ("there's no Twitch channel called …"), other errors `PanelError` + Retry. Header: avatar, display name, login · partner/affiliate, "open on Twitch ↗".
- **Sites**: all four load in parallel with the Twitch id (`useQueries`), each with its own loading / error / empty state, so one failing site never blocks the others. Twitch through core (`GET /twitch/channels/:id/emotes`), the others straight from the browser: 7TV `7tv.io/v3/users/twitch/<id>` (the set's emotes under the channel's alias, files picked as in Browse), BTTV `api.betterttv.net/3/cached/users/twitch/<id>` (channel + shared emotes; `3x.gif|png`, preview `2x.webp`; no custom headers, its preflight answers 403), FFZ `api.frankerfacez.com/v1/room/id/<id>` (`sets[room.set]`). A 404 from a site means the channel has no account there: an empty list, "no 7TV emotes on this channel", not an error. `broadcasterType: null` skips the Twitch request and explains that only partners and affiliates have sub, follower and bits emotes.
- **Tabs**: `SegmentedControl` with a count per site (Spinner while loading, `!` in `danger` on error; with a filter, the matches). Without `?provider` the tab is the first site in tab order (Twitch, 7TV, BTTV, FFZ) with emotes, waiting on a site still loading, so it moves at most once.
- **Filter**: by name, client-side and instant, kept across tabs; no matches → "nothing on 7TV matches …" + clear filter.
- **Twitch** groups by type: follower, tier 1/2/3, bits (core's order), one `EmoteMenu` + `EmoteGrid` per group with an h3 and its count: the selection belongs to one list and `EmoteGrid` syncs it with its own emotes, so groups can't share a menu. Other sites are one grid. Selecting and adding work as in Browse (`kind="catalog"`, `?guild` offered first); Twitch files are on `static-cdn.jtvnw.net`, on core's allowed hosts.

## Not found

`NotFoundPage` is the root route's `notFoundComponent` (unknown client routes, including under `/panel`, render it at the root, without the panel chrome) and the component of `/404`, which exists only to be prerendered to `404.html`; Caddy serves that file with status 404 for unknown public paths. Title `404 · tetra`, `noindex`.

- Navbar, footer and a full-height section with a big `404`, a line of copy and "back home".
- Behind it `EmotePile`: about a dozen emotes from the homepage atlas (fewer on small screens: at most `MAX_COVERAGE` of the area) fall in from above with rigid-body physics and can be dragged and thrown. Drawn by one WebGL2 fullscreen pass through the same ASCII filter as the homepage background (shared code in `src/lib/ascii-gl.ts`), but on a flat surface and with no effects: no cursor reveal, trail, dent or intro wave. Each character cell samples the topmost emote with an opaque pixel there; emotes are square bodies, positions and angles go to the shader as a uniform array.
- Physics: `matter-js`, imported dynamically inside the effect, so it is a separate chunk loaded only on this page. Chosen over a hand-written solver because stacking rotated boxes stably (contacts, friction, sleeping-free settling) is the hard part and matter handles it. Fixed 60 Hz steps; dragging is a soft constraint from the pointer to the grabbed point, so release throws with the pointer's speed.
- Input: only the canvas and the button take pointer events. A press on an emote prevents text selection and, on touch, page scrolling; a press on empty space scrolls normally.
- `prefers-reduced-motion`: the pile is simulated up front, so emotes start settled and don't animate; dragging still works.

## Invite

`INVITE_URL` (`src/lib/links.ts`) is `https://tetra.lol/invite`, a 302 from Caddy to `INVITE_LINK` (see project-notes Deployment). `inviteUrlFor(guildId)` adds `?guild=<id>`; Caddy then appends Discord's `guild_id=<id>&disable_guild_select=true`, so the dialog opens on that server. ## SEO

- **Site URL**: `VITE_SITE_URL` at build time (default `https://tetra.lol`, trailing slash stripped), read as `SITE_URL` in `src/lib/seo.ts`. Used for canonicals, `og:url`, `og:image` (absolute), the sitemap and robots.txt's `Sitemap` line. Vite inlines it into the pages; the build script reads the same module under Bun (`import.meta.env` is `process.env` there).
- **Indexable**: `/`, `/editor`, `/branding` (the brand book's cover) and its four chapters (`/branding/guide`, `/branding/logo`, `/branding/static-logo`, `/branding/feedback`), `/panel` = the keys of `SEO_PAGES`. Every chapter the cover links to is indexable: a public book with hidden chapters made no sense. Each route's `head: () => seoHead("<key>")` gives title, description, canonical, Open Graph (`og:type` website, site name, url, title, description, 1200×630 image + alt) and a `summary_large_image` Twitter card. Root `__root.tsx` has the site-wide fallbacks: title `Tetra`, the home description, `theme-color` (`#0b0a09` = `background`), the favicons.
- **Head merging** (TanStack Router): `meta` merges by `name`/`property` (and `title`) with the deepest route winning; `links` are concatenated from every match, never deduplicated. So a canonical on a layout shows up on all its children, and a `noindex` on a layout can't be undone by a child. `panel.tsx` therefore returns `seoHead("panel")` only when the deepest match is `/panel` or `/panel/` (head runs again on every navigation), and `noindex` sits on leaf routes only.
- **The shell**: `_shell.html` is rendered with `maskPath: "/panel"` and `ssr: false` stops below `/panel`, so it gets root + `panel.tsx`'s head: the /panel title, description, OG and canonical, no `noindex`. A `head` on `panel.index.tsx` never reaches it. Every other path the shell serves (`/panel/*`, `/editor/$key`) swaps in its own head on the client.
- **Not indexed**: `/panel/*` children and `/editor/$key` put `NOINDEX_META` in their own `head` (Google renders JS). A new panel route needs it too.
- **robots.txt, sitemap.xml and llms.txt** are server routes (`src/routes/robots[.]txt.ts`, `sitemap[.]xml.ts`, `llms[.]txt.ts`, content in `src/lib/seo-files.ts`), so they answer in `vite dev` too; the build prerenders them to plain files (`staticFiles` in `vite.config.ts`).
- **robots.txt**: `Allow: /`, `Allow: /panel/$`, `Allow: /editor/$`, `Disallow: /panel/`, `Disallow: /editor/`. Google applies the longest matching rule (`$` anchors the end), so `/panel` and `/editor` match no Disallow, and `/panel/` / `/editor/` stay allowed in case the host redirects a directory to its trailing-slash form; everything below them is blocked. Noindexed pages stay crawlable on purpose: a disallowed URL can't show Google its `noindex`.
- **sitemap.xml**: the `SEO_PAGES` paths, absolute.
- **llms.txt** ([llmstxt.org](https://llmstxt.org)): a plain-text map for AI assistants, the home description, one line on what tetra is, then every `SEO_PAGES` entry as `[title](url): description`. Built from `SEO_PAGES`, so it never says more than the pages do.
- **OG images**: `scripts/build-seo.tsx` draws one 1200×630 PNG per `SEO_PAGES` key to `dist/client/og/<key>.png` with satori (JSX → SVG) + `@resvg/resvg-js`, about 1 s for all. Fonts: static TTFs from the `geist` package (satori reads ttf/otf/woff, not woff2); Geist Serif ships only as woff2 and is decompressed with `wawoff2`. resvg doesn't read `oklch()`, so the script converts the brand tokens. Layout: `background`, an ASCII texture of the ramp on a 11px Geist Mono grid (seeded value noise, `muted` at 16%, quieter behind the text), the white logo square top left and, level with it on the right margin, the word `tetra` in orange ASCII: Geist Serif with a 5% stroke so the hairlines survive, letter-spaced 0.06em, sampled per cell on its own finer grid (7px Geist Mono 900, 12 rows; the serif needs about a dozen rows to read, so a smaller word means smaller cells, as on the Discord banners), dense `#%@` inside the letters and `*`/`+` on the edges, with the texture cleared under them. Bottom left: the eyebrow in muted mono (no `[NN]` index: the page order meant nothing), the heading with its serif accent, and the description in `muted`. Seeded per page, so builds are byte-identical. Keep heading + accent on one line (about 20 characters + one accent word); a wrapped accent starts its own line.
- **JSON-LD**: `jsonLdScript(data)` in `seo.ts` turns schema.org data into a `head().scripts` entry (`type: application/ld+json`, `<` escaped). `/` carries `HOME_JSON_LD` (`SoftwareApplication` on Discord, no price: premium isn't settled). `/editor` carries `EDITOR_JSON_LD` (`WebApplication`, free offer, feature list, description = the page's SEO description) next to `seoHead("editor")` in `editor.index.tsx`. No `FAQPage` schema: Google shows FAQ results only for authoritative government and health sites; the editor's FAQ is plain content. TanStack also supports `{ "script:ld+json": data }` inside `meta`; `scripts` was picked to keep it out of the meta merging.
- **Editor content for search**: `/editor` targets queries like "discord emote resizer", "gif too big for discord emoji", "256kb limit". Its title leads with the keywords (`Discord emote resizer and GIF compressor · 256 KB limit · tetra`), the H1 says `make any GIF fit Discord's 256 KB emote limit`, and below the drop zone a how-it-works list and an FAQ (h2 + h3 questions, plain text answers) sit in the prerendered HTML (`EditorGuide` in `editor.index.lazy.tsx`, public host only; the panel's start screen doesn't have it). Only verified facts there: 256 KB, 20 MB cap, 10 recent files, 22/48 px chat sizes from the editor's chat preview, core's 128 px max side.
- **Copy casing**: titles, descriptions and OG texts follow [voice.md](voice.md) (lowercase starts, no trailing period); a title may start with a proper noun (`Discord …`). Buttons write `add to discord` lowercase (owner's call, see voice.md).
- **Adding an indexable page**: an entry in `SEO_PAGES` (path, title, description, `og` eyebrow/heading/accent), `head: () => seoHead("<key>")` on the route, plus `staticPages` and the footer as above. Run `bun run build:seo` after a build (or the whole `build`) and look at the PNG.
- Rejected: generating in a Vite plugin (`import.meta.env` isn't set while the config loads, and the PNGs aren't needed in dev).
- resvg's `RenderedImage.pixels` is a getter that copies the whole buffer on every read; reading it per pixel crashed Bun. Read it once.

## Analytics

Google Analytics 4 (gtag.js), on the site, the editor and the panel. No consent banner: the owner chose to load it for every visitor and accepted the GDPR risk, so don't add consent UI unless asked.

- **Measurement ID**: `VITE_GA_MEASUREMENT_ID` at build time (`G-XXXXXXXXXX`, typed in `src/vite-env.d.ts`). Unset or empty: no script, no listener, `track` does nothing, so `vite dev` and builds without it send no data.
- **Loading**: `analyticsScripts` (`src/lib/analytics.ts`) goes into the root route's `head().scripts`: gtag.js `async` plus the inline `dataLayer` / `gtag("js")` / `gtag("config", id)` init. Being on the root, it lands in every prerendered page and in `_shell.html` (checked in the build output: `index.html`, `editor/index.html`, `404.html`, `_shell.html`; none of them has it when the variable is empty).
- **Page views**: GA4's enhanced measurement counts history (`pushState`) changes as page views, which covers client-side navigation. Never send `page_view` on route changes: every view would count twice. Keep "page changes based on browser history events" on in the GA data stream settings.
- **Events**: `track(event, params)`, typed by `AnalyticsEvents`; a no-op when `window.gtag` is missing (no ID, prerender, blocked by an ad blocker).
  - `invite_click` `{ location }`: one capturing `click` / middle-button `auxclick` listener on the document (`listenForInviteClicks`, started in `RootComponent`) catches every link whose path is `/invite`, so new invite links need nothing. `/invite` is Caddy's 302, GA would never see it otherwise. `location` is the nearest `data-track-location` (`hero`, `home-cta`), else the nearest `footer`, `nav` or `header`, else `page`; GA's page location tells the pages apart. A plain left click (no modifier, no `_blank`) is prevented and navigates from gtag's `event_callback` (or after 800 ms if it never fires, e.g. ad blocker): `/invite` unloads the page at once and the hit was lost before. Modified and middle clicks only send it with `transport_type: "beacon"`. Without `window.gtag` the click isn't touched.
  - `emote_add` `{ source }`: on a successful add to a Discord server. `useAddEmote` (Quick add, Browse, Channel emotes, the emote menu and selection bar) sends the emote's `EmoteSource` (`7tv`, `bttv`, `ffz`, `twitch`, `link`, `discord` for a copy from another server); `useUploadEmote` (the editor's Add to server) sends `file`; `useAddTaskEmote` (the task editor) sends `task`.
  - `panel_login`: the click on "log in with discord" in `PanelLogin`, before the navigation to the API.
